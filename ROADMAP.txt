================================================================================
  IMGFLOW — Product & Technical Roadmap
================================================================================

VISION
------
ImgFlow est un hub d'outils en ligne de traitement d'images et de PDFs,
ciblant deux audiences :

  1. Utilisateurs grand public (trafic SEO)
       - Convertir des images
       - Compresser des images
       - Redimensionner des images
       - Convertir des images et des PDFs

  2. Développeurs (API monétisée)
       - API de conversion d'images
       - Traitement en batch
       - Automatisation de workflows

Objectif :
  Construire un hub d'outils qui génère du trafic SEO et convertit
  un pourcentage d'utilisateurs en clients API payants.

Objectifs long terme :
  - 100 000 visiteurs / mois
  - 2 % de conversion en utilisateurs payants
  - €1 500 – €5 000 / mois de revenus estimés

================================================================================
  STACK TECHNIQUE
================================================================================

  Frontend   : Next.js + TailwindCSS
  Backend    : Node.js + Fastify (ou Express)
  Base DB    : PostgreSQL (Railway)
  Stockage   : Cloudflare R2 (ou S3)
  Email      : Nodemailer + Gmail en dev / Resend en prod (domaine requis)
  Images     : Sharp
  Queue      : Redis + BullMQ (introduit en Phase 3, pas en MVP)
  Paiement   : Stripe
  Hébergement: Railway

================================================================================
  ARCHITECTURE BACKEND
================================================================================

  Frontend
    ↓
  API Server (Fastify / Express)
    ↓
  Job Queue — Redis + BullMQ  [introduit Phase 3]
    ↓
  Worker Process
    ↓
  Stockage (R2 / S3)

  Note MVP (Phase 1-2) :
    Pas de queue — traitement synchrone avec Sharp.
    Une conversion WebP→PNG prend ~50ms, inutile d'over-engineer au départ.

================================================================================
  SCHÉMA BASE DE DONNÉES
================================================================================

  users
    id             SERIAL PRIMARY KEY
    email          TEXT UNIQUE NOT NULL
    password_hash  TEXT
    plan           TEXT DEFAULT 'free'
    created_at     TIMESTAMPTZ DEFAULT NOW()

  files
    id             SERIAL PRIMARY KEY
    user_id        INTEGER REFERENCES users(id)
    filename       TEXT NOT NULL
    storage_url    TEXT NOT NULL
    mimetype       TEXT NOT NULL
    size           INTEGER NOT NULL        -- en octets
    expires_at     TIMESTAMPTZ NOT NULL    -- suppression automatique
    created_at     TIMESTAMPTZ DEFAULT NOW()

  jobs
    id             SERIAL PRIMARY KEY
    user_id        INTEGER REFERENCES users(id)
    tool           TEXT NOT NULL           -- ex: 'webp-to-png'
    status         TEXT DEFAULT 'pending'  -- pending / processing / done / failed
    input_file     INTEGER REFERENCES files(id)
    output_file    INTEGER REFERENCES files(id)
    error          TEXT                    -- message si échec
    created_at     TIMESTAMPTZ DEFAULT NOW()

  api_keys
    id             SERIAL PRIMARY KEY
    user_id        INTEGER REFERENCES users(id)
    key            TEXT UNIQUE NOT NULL
    name           TEXT                    -- label utilisateur, ex: "prod key"
    last_used_at   TIMESTAMPTZ
    created_at     TIMESTAMPTZ DEFAULT NOW()

  api_usage
    id             SERIAL PRIMARY KEY
    user_id        INTEGER REFERENCES users(id)
    api_key_id     INTEGER REFERENCES api_keys(id)
    tool           TEXT NOT NULL
    created_at     TIMESTAMPTZ DEFAULT NOW()

  subscriptions
    id                  SERIAL PRIMARY KEY
    user_id             INTEGER REFERENCES users(id)
    stripe_customer_id  TEXT
    plan                TEXT
    status              TEXT
    created_at          TIMESTAMPTZ DEFAULT NOW()

================================================================================
  PHASE 1 — MVP Core  [Semaines 1–2]
================================================================================

Objectif :
  Shipper le premier outil fonctionnel sans auth, sans queue,
  sans S3. Valider que l'outil de conversion fonctionne.

  [x] Conversion WebP → PNG (synchrone avec Sharp)
  [x] Upload de fichier
  [x] Téléchargement du fichier converti
  [ ] Traitement en mémoire / dossier /tmp (pas de S3 en MVP)
  [ ] Page d'outil simple avec UI drag & drop
  [ ] Affichage du résultat + bouton de téléchargement

  Note : Pas d'authentification en Phase 1.
         Pas de job queue. Sharp est synchrone, ~50ms par conversion.

================================================================================
  PHASE 2 — Auth + Stockage + Multi-outils  [Semaines 2–4]
================================================================================

Objectif :
  Ajouter l'authentification, migrer vers R2 pour le stockage,
  et étendre la palette d'outils (images + PDFs).

  [ ] Inscription / connexion / déconnexion
  [ ] Vérification par email
  [ ] Réinitialisation de mot de passe
  [ ] Stockage des fichiers sur Cloudflare R2
  [ ] Politique d'expiration des fichiers (24h free, 30j Pro)
  [ ] Cron job ou lifecycle rule R2 pour nettoyer les fichiers expirés

  Outils image à implémenter :
    [ ] WebP → PNG
    [ ] PNG → WebP
    [ ] JPG → PNG
    [ ] PNG → JPG
    [ ] HEIC → JPG
    [ ] Compression d'image (afficher le gain en %)
    [ ] Redimensionnement (largeur × hauteur, avec gestion des proportions)
    [ ] Rotation / recadrage
    [ ] Suppression des métadonnées EXIF

  Outils PDF à implémenter :
    [ ] Image → PDF
    [ ] PDF → JPG
    [ ] Compression PDF
    [ ] Fusion de PDFs
    [ ] Découpage de PDF

  Structure des URLs (une seule convention, pas de duplication) :
    /tools/webp-to-png
    /tools/png-to-webp
    /tools/jpg-to-png
    /tools/compress-image
    /tools/resize-image
    /tools/crop-image
    /tools/image-to-pdf
    /tools/pdf-to-jpg
    /tools/compress-pdf
    /tools/merge-pdf

  Chaque page doit contenir :
    - Interface de l'outil
    - Contenu SEO (500–800 mots)
    - Section FAQ avec schema markup
    - Liens internes vers outils similaires

================================================================================
  PHASE 3 — Dashboard + Job Queue  [Semaines 4–5]
================================================================================

Objectif :
  Permettre aux utilisateurs de gérer leurs fichiers et clés API.
  Introduire BullMQ pour les traitements lourds (batch, PDF).

  Dashboard utilisateur (/dashboard) :
    [ ] Historique des conversions
    [ ] Re-téléchargement des fichiers (dans la limite de rétention)
    [ ] Quota utilisé ce mois
    [ ] Gestion des clés API (créer, nommer, révoquer)
    [ ] Paramètres du compte

  Job Queue (Redis + BullMQ) :
    [ ] File de traitement asynchrone
    [ ] Worker séparé pour les images
    [ ] Worker séparé pour les PDFs
    [ ] Statut du job en temps réel (polling ou WebSocket)

  Flow de traitement :
    1. Utilisateur uploade un fichier
    2. Serveur stocke le fichier sur R2
    3. Job créé dans la queue Redis
    4. Worker traite le fichier
    5. Résultat stocké sur R2
    6. Utilisateur reçoit le lien de téléchargement

  Traitement en batch :
    [ ] Upload ZIP → traitement de toutes les images → téléchargement ZIP

================================================================================
  PHASE 4 — API Publique  [Semaines 5–6]
================================================================================

Objectif :
  Lancer une API REST pour les développeurs.

  Endpoints :
    POST /api/v1/convert
    POST /api/v1/compress
    POST /api/v1/resize
    POST /api/v1/crop

  Authentification :
    Authorization: Bearer API_KEY

  Exemple de réponse :
    {
      "url": "https://cdn.imgflow.io/output/file.png",
      "size": 48200,
      "expires_at": "2024-12-01T00:00:00Z"
    }

  Rate limiting par plan :
    Free     : 100 conversions / mois
    Pro      : 10 000 conversions / mois
    Business : 100 000 conversions / mois

  [ ] Tracking de l'usage via table api_usage
  [ ] Documentation de l'API avec exemples curl / Node / Python
  [ ] Page développeur avec playground interactif
